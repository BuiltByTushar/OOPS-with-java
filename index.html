Q1 (a) Platform Independence, JVM, and a Missing public static
Marks 4 · compulsory CO1 BL4 PO1,2 PI 1.7.1, 2.8.4
Illustrate the reasons behind Java's platform independence. Is JVM itself platform-independent? If public and static are removed from the main method, what error will occur at the console and why? Explain in detail.

Java follows "Write Once, Run Anywhere." The mechanism behind it:

Java source (.java)
   ↓  javac (compiler)
Java bytecode (.class)   — platform-neutral, the same on every OS
   ↓  JVM (interprets/JIT-compiles the bytecode)
Machine-specific execution
  1. Source code is compiled once into bytecode, not directly into machine code.
  2. Bytecode is a fixed, platform-neutral instruction format — identical on Windows, Linux, or macOS.
  3. Each OS has its own native JVM build that knows how to interpret that same bytecode.
  4. So the same .class file runs unmodified wherever a compatible JVM exists.
Answer

Java is platform independent because compilation stops at bytecode — a format every JVM understands — rather than producing OS-specific machine code directly.

No. This is the detail that's easy to mix up: the bytecode is platform-independent, but the JVM that runs it is not. Each JVM build is native machine code compiled specifically for one OS/CPU combination (a Windows JVM, a Linux JVM, a macOS JVM, etc.) so it can talk to that system's memory manager, threads, and file system.

Answer

Bytecode → platform independent. JVM → platform dependent (a separate native build is required per OS/architecture).

The JVM launcher looks for one exact signature to start a program:

public static void main(String[] args)

Each keyword is load-bearing: public — the launcher (outside the class) must be able to call it; static — the JVM must invoke it without first constructing an object; void — the launcher doesn't use a return value; String[] args — carries command-line arguments.

I actually compiled and ran all three "broken" variants to get the exact console text (OpenJDK 21):

Java

}
$ java Demo Error: Main method not found in class Demo, please define the main method as: public static void main(String[] args) or a JavaFX application class must extend javafx.application.Application
Java
public class Demo {
    // public, but NOT static
    public void main(String[] args) { System.out.println("Hello"); }
}
$ java Demo Error: Main method is not static in class Demo, please define the main method as: public static void main(String[] args)
Java
class Demo {
    // static, but NOT public
    static void main(String[] args) { System.out.println("Hello"); }
}
$ java Demo Error: Main method not found in class Demo, please define the main method as: public static void main(String[] args) or a JavaFX application class must extend javafx.application.Application
✓ compiled & run — OpenJDK 21.0.10

In every case the program still compiles fine (it's syntactically valid Java) — the failure only happens when the launcher goes looking for a runnable entry point and can't find one matching the required signature.

Exam-safe summary: older JDKs collapse all three cases into one generic "main method not found" message; JDK 8+ (including the 21 tested here) is smarter about the "not static" case specifically. Either way, the concept to state is the same: the launcher requires exactly public static void main(String[] args), and any deviation is treated as "no valid entry point," not a compile error.
Q1 (b) Trace the Output of Two Given Java Programs
Marks 4 CO1 BL3 PO1 PI 1.7.1
Two independent programs are given — trace and state the output of each.
Java
class ObjectPassDemo {
    int a, b;
    ObjectPassDemo(int i, int j) { a = i; b = j; }
    boolean equalTo(ObjectPassDemo o) {
        return (o.a == a && o.b == b);
    }
}
public class test {
    public static void main(String args[]) {
        ObjectPassDemo ob1 = new ObjectPassDemo(100, 22);
        ObjectPassDemo ob2 = new ObjectPassDemo(100, 22);
        ObjectPassDemo ob3 = new ObjectPassDemo(-1, -1);
        System.out.println("ob1 == ob2: " + ob1.equalTo(ob2));
        System.out.println("ob1 == ob3: " + ob1.equalTo(ob3));
    }
}

Trace: ob1.equalTo(ob2) compares ob1's fields (100,22) against ob2's (100,22) — both match, so true. ob1.equalTo(ob3) compares (100,22) against (−1,−1) — 100≠−1 fails immediately (short-circuit &&), so false.

ob1 == ob2: true ob1 == ob3: false
✓ compiled & run
The key concept here: equalTo() compares the field values inside the objects. Plain ob1 == ob2 would instead compare object references (memory identity) and would be false, even though the data is identical — the classic == vs .equals()-style distinction.
Java
class test {
    static int ans[];
    test() {
        this(6, 4);
    }
    test(int a, int b) {
        ans = new int[2];
        ans[0] = a + b;
        ans[1] = a - b;
    }
    public static void main(String[] args) {
        test t = new test();
        System.out.println("Add= " + ans[0]);
        System.out.println("Sub = " + ans[1]);
    }
}

Trace: new test() calls the no-arg constructor, which immediately delegates via this(6,4) — this is constructor chaining. The parameterized constructor then runs with a=6, b=4: allocates ans, sets ans[0]=6+4=10 and ans[1]=6−4=2.

Add= 10 Sub = 2
✓ compiled & run
Answer

(i) prints true then false. (ii) prints Add= 10 then Sub = 2. Note both programs declare a class named test — that's fine since they're two separate source files/programs, not one combined file (Java doesn't allow two same-named top-level public classes in one file).

Q1 (c) Exception Handling — throw vs throws
Marks 4 CO1,2 BL5 PO2,3 PI 2.6, 3.6
Write a Java program for handling exceptions. Show the difference between throw and throws with the help of a suitable example.
throwthrows
Actually raises an exception, right there in the codeJust declares that a method might raise a checked exception
Used inside a method bodyUsed in the method signature
Followed by a single exception objectFollowed by one or more exception class names
throw new IllegalArgumentException("...")void readFile() throws IOException
Java
import java.io.*;

public class ThrowThrows {

    static void checkAge(int age) {
        if (age < 18) {
            // throw: actively raising an exception
            throw new IllegalArgumentException("Age is less than 18");
        }
        System.out.println("Eligible to vote");
    }

    // throws: declaring that this method may raise IOException
    static void readFile() throws IOException {
        FileInputStream f = new FileInputStream("nonexistent_data.txt");
        f.close();
    }

    public static void main(String[] args) {
        try {
            checkAge(15);
        } catch (IllegalArgumentException e) {
            System.out.println("Caught: " + e.getMessage());
        }

        try {
            readFile();
        } catch (IOException e) {
            System.out.println("Caught file exception: " + e.getMessage());
        }
    }
}
Caught: Age is less than 18 Caught file exception: nonexistent_data.txt (No such file or directory)
✓ compiled & run
Answer

throw is an action (raise this exception now); throws is a declaration on the method signature warning callers "this might fail, you must catch or re-declare it." readFile() uses throws IOException because FileInputStream's constructor raises a checked exception that Java forces you to acknowledge at compile time.

Q2 (a) Dynamic Method Dispatch & Runtime Polymorphism
Marks 3 · compulsory CO1,2 BL4 PO1,2 PI 1.7, 2.6
With a suitable example, explain Dynamic Method Dispatch in detail. How does it support run-time polymorphism?

Dynamic Method Dispatch is the mechanism by which Java decides, at runtime, which overridden method to execute — based on the actual object type, not the type of the reference variable pointing to it. This is exactly how Java implements runtime polymorphism.

Java
class Animal {
    void sound() { System.out.println("Animal makes a sound"); }
}
class Dog extends Animal {
    void sound() { System.out.println("Dog barks"); }
}
class Cat extends Animal {
    void sound() { System.out.println("Cat meows"); }
}
public class DMD {
    public static void main(String[] args) {
        Animal a;
        a = new Dog();
        a.sound();
        a = new Cat();
        a.sound();
    }
}
Dog barks Cat meows
✓ compiled & run

Reference type is always Animal; which sound() runs is decided by the object actually stored — resolved at runtime, not compile time.

Answer

Even though a is declared as type Animal, calling a.sound() invokes whichever subclass actually overrode sound() for the object currently referenced — Dog's version, then Cat's. The JVM looks up the method on the object's class (via the vtable) at call time, which is precisely what makes overriding useful and is the basis of runtime polymorphism.

Q2 (b) Interfaces, Default Methods, Full vs Partial Implementation
Marks 3 CO1,2 BL3 PO1,3 PI 1.7, 3.6
State the purpose of interface in Java. What is the role of a default method in interface? With suitable example(s), explain full and partial implementation of interface.

An interface defines a pure contract — a set of methods a class promises to provide, without saying how. It's Java's way of achieving abstraction, allowing unrelated classes to share a common type, and giving "multiple inheritance of type" (a class can implement several interfaces even though it can extend only one class).

Java
interface Vehicle {
    void start();
    void stop();
}

From Java 8 onward, an interface may include a default method — a method with a real body. Implementing classes inherit it automatically and are free to leave it as-is or override it. This let interfaces evolve (add new methods) without breaking every class that already implements them.

Java
interface Vehicle {
    void start();
    default void horn() { System.out.println("Beep beep"); }
}
class Car implements Vehicle {
    public void start() { System.out.println("Car starts"); }
    // horn() is inherited as-is — no override needed
}

Full implementation: a concrete class implements every abstract method of the interface.

Java
interface Shape {
    void area();
    void draw();
}
class Circle implements Shape {
    public void area() { System.out.println("Area of circle"); }
    public void draw() { System.out.println("Drawing circle"); }
}

Partial implementation: an abstract class implements only some of the interface's methods, leaving the rest for a concrete subclass. Java allows this specifically because abstract classes are never instantiated directly.

Java
abstract class ShapeBase implements Shape {
    public void area() { System.out.println("Area calculation"); }
    // draw() left unimplemented -> class MUST stay abstract
}
class Square extends ShapeBase {
    public void draw() { System.out.println("Drawing square"); }
}
Answer

Interfaces give a contract + abstraction + multiple type-inheritance. default methods let an interface ship a ready-made behaviour. A concrete class must give a full implementation; an abstract class may give a partial one and hand the rest down to its subclasses.

Q2 (c) final, finally, and super
Marks 3 CO1 BL2 PO1 PI 1.7
With suitable examples, explain the use of final and finally keyword(s). Also, describe the purpose of the super keyword in accessing parent class members.
final int MAX = 100;  // value can never be reassigned
final void show(){...}  // a subclass cannot override this method
final class Parent {...}  // no class may extend Parent
Java
try {
    int x = 10 / 2;
    System.out.println(x);
} catch (ArithmeticException e) {
    System.out.println("Error");
} finally {
    System.out.println("Finally block executed");
}
5 Finally block executed

The finally block runs whether or not an exception occurred (and even if the try block returns) — the standard place to close files, connections, or streams.

super refers to the immediate parent class and has three uses: accessing a shadowed field, calling an overridden method, and invoking a parent constructor.

Java
class Parent {
    int x = 10;
    void show() { System.out.println("Parent method"); }
}
class Child extends Parent {
    int x = 20;
    void show() {
        super.show();
        System.out.println("Child x = " + x);
        System.out.println("Parent x (via super) = " + super.x);
    }
}
public class FinalSuper {
    public static void main(String[] args) {
        new Child().show();
    }
}
Parent method Child x = 20 Parent x (via super) = 10
✓ compiled & run
Answer

final locks something down (no reassignment / no override / no subclassing). finally guarantees cleanup code runs regardless of exceptions. super reaches past a subclass's own fields/methods/constructor to the parent's version — essential whenever a subclass shadows or overrides something but still needs the original.

Q3 (a) Multithreading, setPriority() and isAlive()
Marks 3 CO1,2 BL4 PO1,2 PI 1.7, 2.8
State the purpose of Multithread programming with suitable example. Explain the use of setPriority() and isAlive() methods of Thread class with suitable example.

Multithreading lets a single program run multiple independent paths of execution ("threads") concurrently — improving responsiveness, CPU utilisation, and letting background work (downloads, I/O, animation) proceed without freezing the rest of the program.

Thread priorities range from 1 to 10 (Thread.MIN_PRIORITY=1, NORM_PRIORITY=5, MAX_PRIORITY=10) — a hint to the scheduler, not a guarantee of execution order. isAlive() reports whether a thread has been started and hasn't yet finished.

Java
class MyThread extends Thread {
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println("Priority " + this.getPriority() + " running: " + i);
        }
    }
}
public class ThreadDemo {
    public static void main(String[] args) throws InterruptedException {
        MyThread t = new MyThread();
        t.setPriority(Thread.MAX_PRIORITY);
        System.out.println("Before start, isAlive = " + t.isAlive());
        t.start();
        System.out.println("Right after start, isAlive = " + t.isAlive());
        t.join();
        System.out.println("After join (finished), isAlive = " + t.isAlive());
    }
}
Before start, isAlive = false Right after start, isAlive = true Priority 10 running: 1 Priority 10 running: 2 Priority 10 running: 3 After join (finished), isAlive = false
✓ compiled & run
Answer

setPriority(int) assigns a scheduling priority 1–10 (here MAX_PRIORITY=10). isAlive() is false before start(), becomes true the moment the thread has started and not yet finished, and returns to false once it terminates — exactly as shown above.

Q3 (b) Java Applet — "This is MMMUT" & the Applet Life Cycle
Marks 3 CO4 BL3 PO1 PI 1.7.1
Write a Java Applet program to display the text "This is MMMUT". Also, explain the Applet Life Cycle in detail.
Java
import java.applet.Applet;
import java.awt.Graphics;

public class MMMUTApplet extends Applet {

    public void init()  { /* one-time setup */ }
    public void start() { /* runs each time applet becomes active */ }

    public void paint(Graphics g) {
        g.drawString("This is MMMUT", 50, 50);
    }

    public void stop()    { /* runs when applet becomes inactive */ }
    public void destroy() { /* final cleanup */ }
}
✓ compiles clean on JDK 21 (with a removal-deprecation warning — see note below)
Applet Life Cycle

paint() may fire many times while the applet is active (any time it needs to redraw).

MethodWhen it runs
init()Once, right when the applet is first loaded — setup, load resources
start()After init(), and again every time the applet becomes active (e.g. page revisited)
paint(Graphics g)Whenever the applet needs to (re)draw its output — can run many times
stop()When the applet becomes inactive (user leaves the page)
destroy()Once, right before the applet is unloaded — final cleanup
Worth knowing for the exam and beyond: the Applet API is still present in JDK 21 (it compiles — I checked), but the compiler flags it with a "has been deprecated and marked for removal" warning, and browser plugin support / the appletviewer tool were removed years ago. It's taught for the life-cycle concept, but isn't how modern Java GUI work is actually done anymore (that's Swing/JavaFX territory).
Answer

Life cycle order: init() → start() → paint() → stop() → destroy(), with start()/stop() able to repeat if the applet is revisited before final destruction.

Q3 (c) AWT Layout Managers & a Simple Login Form
Marks 3 CO5 BL3 PO1,3 PI 1.7.1, 3.6.2
Briefly explain the role of Layout Managers in AWT. Using AWT, write a program to design a simple form layout (username / password fields with OK / Cancel buttons, per the paper's sketch).

A layout manager automatically positions and sizes the components inside a container, so the programmer never hand-codes pixel coordinates — the layout adapts if the window is resized or components are added/removed.

LayoutBehaviour
FlowLayoutPlaces components left-to-right, wrapping to a new line as needed — the default for Panel
BorderLayoutDivides the container into NORTH / SOUTH / EAST / WEST / CENTER regions — the default for Frame
GridLayoutArranges components into a strict rows × columns grid of equal-sized cells
Why GridLayout fits this form: the sketch needs two label+field rows plus a button row, all neatly aligned in two columns — exactly what GridLayout(3,2) gives for free.
Java
import java.awt.*;
import java.awt.event.*;

public class LoginForm extends Frame {

    LoginForm() {
        setTitle("AWT Example");
        setLayout(new GridLayout(3, 2, 10, 10));

        add(new Label("Enter username"));
        TextField username = new TextField();
        add(username);

        add(new Label("Enter password"));
        TextField password = new TextField();
        password.setEchoChar('*');
        add(password);

        add(new Button("OK"));
        add(new Button("Cancel"));

        setSize(320, 160);
        addWindowListener(new WindowAdapter() {
            public void windowClosing(WindowEvent e) { dispose(); }
        });
    }

    public static void main(String[] args) {
        LoginForm f = new LoginForm();
        f.setVisible(true);
    }
}
✓ compiles clean — OpenJDK 21, zero warnings
Answer

Layout managers handle component placement automatically. For this username/password/OK/Cancel form, GridLayout(3,2,10,10) lines everything up in three rows of two columns (label+field, label+field, button+button), matching the sketch directly.

Q1 (a) Platform Independence, JVM, and a Missing public static
Marks 4 · compulsory CO1 BL4 PO1,2 PI 1.7.1, 2.8.4
Illustrate the reasons behind Java's platform independence. Is JVM itself platform-independent? If public and static are removed from the main method, what error will occur at the console and why? Explain in detail.

Java follows "Write Once, Run Anywhere." The mechanism behind it:

Java source (.java)
   ↓  javac (compiler)
Java bytecode (.class)   — platform-neutral, the same on every OS
   ↓  JVM (interprets/JIT-compiles the bytecode)
Machine-specific execution
  1. Source code is compiled once into bytecode, not directly into machine code.
  2. Bytecode is a fixed, platform-neutral instruction format — identical on Windows, Linux, or macOS.
  3. Each OS has its own native JVM build that knows how to interpret that same bytecode.
  4. So the same .class file runs unmodified wherever a compatible JVM exists.
Answer

Java is platform independent because compilation stops at bytecode — a format every JVM understands — rather than producing OS-specific machine code directly.

No. This is the detail that's easy to mix up: the bytecode is platform-independent, but the JVM that runs it is not. Each JVM build is native machine code compiled specifically for one OS/CPU combination (a Windows JVM, a Linux JVM, a macOS JVM, etc.) so it can talk to that system's memory manager, threads, and file system.

Answer

Bytecode → platform independent. JVM → platform dependent (a separate native build is required per OS/architecture).

The JVM launcher looks for one exact signature to start a program:

public static void main(String[] args)

Each keyword is load-bearing: public — the launcher (outside the class) must be able to call it; static — the JVM must invoke it without first constructing an object; void — the launcher doesn't use a return value; String[] args — carries command-line arguments.

Q2 (a) Dynamic Method Dispatch & Runtime Polymorphism
Marks 3 · compulsory CO1,2 BL4 PO1,2 PI 1.7, 2.6
With a suitable example, explain Dynamic Method Dispatch in detail. How does it support run-time polymorphism?

Dynamic Method Dispatch is the mechanism by which Java decides, at runtime, which overridden method to execute — based on the actual object type, not the type of the reference variable pointing to it. This is exactly how Java implements runtime polymorphism.

Java
class Animal {
    void sound() { System.out.println("Animal makes a sound"); }
}
class Dog extends Animal {
    void sound() { System.out.println("Dog barks"); }
}
class Cat extends Animal {
    void sound() { System.out.println("Cat meows"); }
}
public class DMD {
    public static void main(String[] args) {
        Animal a;
        a = new Dog();
        a.sound();
        a = new Cat();
        a.sound();
    }
}
Dog barks Cat meows
✓ compiled & run

Reference type is always Animal; which sound() runs is decided by the object actually stored — resolved at runtime, not compile time.

Answer

Even though a is declared as type Animal, calling a.sound() invokes whichever subclass actually overrode sound() for the object currently referenced — Dog's version, then Cat's. The JVM looks up the method on the object's class (via the vtable) at call time, which is precisely what makes overriding useful and is the basis of runtime polymorphism.

Q2 (b) Interfaces, Default Methods, Full vs Partial Implementation
Marks 3 CO1,2 BL3 PO1,3 PI 1.7, 3.6
State the purpose of interface in Java. What is the role of a default method in interface? With suitable example(s), explain full and partial implementation of interface.

An interface defines a pure contract — a set of methods a class promises to provide, without saying how. It's Java's way of achieving abstraction, allowing unrelated classes to share a common type, and giving "multiple inheritance of type" (a class can implement several interfaces even though it can extend only one class).

Java
interface Vehicle {
    void start();
    void stop();
}

From Java 8 onward, an interface may include a default method — a method with a real body. Implementing classes inherit it automatically and are free to leave it as-is or override it. This let interfaces evolve (add new methods) without breaking every class that already implements them.

Java
interface Vehicle {
    void start();
    default void horn() { System.out.println("Beep beep"); }
}
class Car implements Vehicle {
    public void start() { System.out.println("Car starts"); }
    // horn() is inherited as-is — no override needed
}

Full implementation: a concrete class implements every abstract method of the interface.

Java
interface Shape {
    void area();
    void draw();
}
class Circle implements Shape {
    public void area() { System.out.println("Area of circle"); }
    public void draw() { System.out.println("Drawing circle"); }
}

Partial implementation: an abstract class implements only some of the interface's methods, leaving the rest for a concrete subclass. Java allows this specifically because abstract classes are never instantiated directly.

Java
abstract class ShapeBase implements Shape {
    public void area() { System.out.println("Area calculation"); }
    // draw() left unimplemented -> class MUST stay abstract
}
class Square extends ShapeBase {
    public void draw() { System.out.println("Drawing square"); }
}
Answer

Interfaces give a contract + abstraction + multiple type-inheritance. default methods let an interface ship a ready-made behaviour. A concrete class must give a full implementation; an abstract class may give a partial one and hand the rest down to its subclasses.

Q3 (a) Multithreading, setPriority() and isAlive()
Marks 3 CO1,2 BL4 PO1,2 PI 1.7, 2.8
State the purpose of Multithread programming with suitable example. Explain the use of setPriority() and isAlive() methods of Thread class with suitable example.

Multithreading lets a single program run multiple independent paths of execution ("threads") concurrently — improving responsiveness, CPU utilisation, and letting background work (downloads, I/O, animation) proceed without freezing the rest of the program.

Thread priorities range from 1 to 10 (Thread.MIN_PRIORITY=1, NORM_PRIORITY=5, MAX_PRIORITY=10) — a hint to the scheduler, not a guarantee of execution order. isAlive() reports whether a thread has been started and hasn't yet finished.

Java
class MyThread extends Thread {
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println("Priority " + this.getPriority() + " running: " + i);
        }
    }
}
public class ThreadDemo {
    public static void main(String[] args) throws InterruptedException {
        MyThread t = new MyThread();
        t.setPriority(Thread.MAX_PRIORITY);
        System.out.println("Before start, isAlive = " + t.isAlive());
        t.start();
        System.out.println("Right after start, isAlive = " + t.isAlive());
        t.join();
        System.out.println("After join (finished), isAlive = " + t.isAlive());
    }
}
Before start, isAlive = false Right after start, isAlive = true Priority 10 running: 1 Priority 10 running: 2 Priority 10 running: 3 After join (finished), isAlive = false
✓ compiled & run
Answer

setPriority(int) assigns a scheduling priority 1–10 (here MAX_PRIORITY=10). isAlive() is false before start(), becomes true the moment the thread has started and not yet finished, and returns to false once it terminates — exactly as shown above.

JVM Internal Architecture: Class Loader loads .class files; Runtime Data Areas hold memory; Execution Engine interprets/JIT-compiles bytecode into native CPU instructions.

Major Components of the JVM:

  • Class Loader Subsystem: Responsible for Loading (loading binary byte data into memory), Linking (verification, preparation of static fields, resolution of symbolic references), and Initialization (executing static initializers).
  • Method Area: Shared across all threads; stores class-level data, bytecode, method signatures, and runtime constant pool.
  • Heap Area: Shared memory area where all Java objects and arrays are allocated (managed by Garbage Collector).
  • Java Thread Stack: Private to each thread; created at thread start; stores local variables, method invocations, and stack frames.
  • PC (Program Counter) Register: Holds the address of the currently executing JVM instruction for each thread.
  • Native Method Stack: Holds native C/C++ method invocations executed via JNI.
  • Execution Engine: Consists of the Interpreter (reads bytecode instruction-by-instruction), JIT Compiler (compiles hotspots to native code), and Garbage Collector.

Thread Synchronization & Preventing Race Conditions

A race condition occurs when two or more threads concurrently access shared mutable state without coordination, producing corrupt or non-deterministic outcomes. For example, balance = balance - amount is not an atomic operation; it involves reading, subtracting, and storing back.

Java provides the synchronized keyword to enforce mutual exclusion on an object's intrinsic monitor lock:

Object Serialization & The transient Keyword

Serialization is the mechanism of converting an in-memory object's state into a byte stream, allowing it to be persisted to a file or transferred across a network. The reverse process is Deserialization.

  • The class must implement the marker interface java.io.Serializable (has no methods).
  • Use ObjectOutputStream.writeObject(obj) to serialize.
  • Use ObjectInputStream.readObject() to deserialize.
  • The transient Keyword: Fields marked transient are skipped during serialization (e.g. security passwords, session keys, temporary calculated values). Upon deserialization, transient fields receive default zero/null values.
Java
import java.io.Serializable;

class StudentRecord implements Serializable {
    private static final long serialVersionUID = 1L;
    String studentName;
    int rollNumber;
    transient String secretPassword; // Will NOT be saved to byte stream!

    public StudentRecord(String name, int roll, String pass) {
        this.studentName = name;
        this.rollNumber = roll;
        this.secretPassword = pass;
    }
}

Applet Loaded into Browser │ ▼ init() <-- One-time initialization │ ▼ ┌─────────► start() <-- Invoked when page becomes visible │ │ │ ▼ │ paint() <-- Renders graphics on canvas │ │ │ ▼ │ stop() <-- Invoked when page is navigated away └─────────────┘ │ ▼ destroy() <-- One-time cleanup before unload

The Five Key Life Cycle Methods:

  1. init(): Invoked only once when the applet is first loaded into memory. Used to initialize variables, allocate GUI components, load fonts, and read <param> tags.
  2. start(): Invoked immediately after init() and whenever the user returns to the webpage after leaving it. Starts background animation threads and audio playback.
  3. paint(Graphics g): Called whenever the applet's display surface must be refreshed or redrawn. The Graphics object provides 2D drawing methods (drawString, drawRect, fillOval, setColor).
  4. stop(): Invoked automatically whenever the browser tab is minimized or the user navigates away to another webpage. Suspends CPU-intensive threads.
  5. destroy(): Invoked only once when the browser completely closes or unloads the applet from cache. Frees allocated native operating system resources.

            System.out.println("[Server] Listening on port 6000. Waiting for client...");

            // accept() blocks until an incoming client initiates connection
            try (Socket socket = serverSocket.accept();
                 DataInputStream in = new DataInputStream(socket.getInputStream());
                 DataOutputStream out = new DataOutputStream(socket.getOutputStream())) {

                System.out.println("[Server] Client connected from: " + socket.getRemoteSocketAddress());
                String clientMsg = in.readUTF();
                System.out.println("[Server] Received: " + clientMsg);

                // Send reply back to client
                out.writeUTF("Server ACK: Message '" + clientMsg + "' received successfully.");
                out.flush();
            }
        } catch (IOException e) {

        }
    }
}

Java GUI programs employ an event-driven programming model where execution flow is dictated by asynchronous user interactions (keystrokes, mouse moves, button clicks, window resize/close events). Modern Java AWT/Swing handles this via the Delegation Event Model.

Why Adapter Classes Exist

Listener interfaces such as WindowListener declare seven separate methods. If a class implements WindowListener directly, it is syntactically forced to provide empty implementations ({}) for all seven methods, even if it only cares about windowClosing()!

An Adapter class (e.g. WindowAdapter, MouseAdapter, KeyAdapter) implements the interface by providing default empty bodies for all methods. You simply extend the adapter and override only the specific method you need.

A Layout Manager is an object implementing the java.awt.LayoutManager interface that automatically calculates the size and position of components inside a container. Why Layout Managers are Critical: Hardcoded pixel positioning (setLayout(null)) inevitably breaks when an application runs on operating systems with different screen DPIs, monitor resolutions, and localized system fonts. Layout managers guarantee dynamic, responsive UI restructuring.

The Five Standard AWT Layout Managers

1. FlowLayout

The default layout for Panel and Applet. Places components in a row from left to right in the order added. When the current horizontal row fills up, it wraps automatically to the next row.

The default layout for Frame and Dialog. Divides the container into five geographic regions: NORTH, SOUTH, EAST, WEST, and CENTER.

Unit II University Question Bank

Top 2-Mark Short Definitions:

  • What is a race condition? An undesirable concurrency bug where the final value of a variable depends on the unpredictable thread execution timing.
  • What is the purpose of the transient keyword? Prevents a specific instance variable from being serialized into the byte stream.
  • Why does an Applet have no main() method? Because its execution is managed by the browser/appletviewer lifecycle container (init(), start()).
  • What is a daemon thread? A low-priority background thread (like Garbage Collector) that does not prevent JVM shutdown when user threads terminate.
  • What is an adapter class? A convenience class implementing a listener interface with empty dummy bodies, sparing subclasses from writing unused methods.
